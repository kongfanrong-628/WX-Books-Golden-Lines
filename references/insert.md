# insert.md — 金句匹配与插入算法

`insert.py` 在写口播/文案时调用知识库，把金句智能嵌入稿件。核心目标：**插入不少于 `min_insert`(默认3) 条，且每条都与文案主题/语境匹配**。

## 输入

```
python insert.py --manuscript 稿件.md --kb <kb_dir或golden_lines.json> --out 增强稿.md --min 3 --max 5
```

- `--manuscript`：口播稿（.md/.txt）；`-` 表示从 stdin 读取
- `--kb`：知识库目录或 `golden_lines.json`
- `--min` / `--max`：最少 / 最多插入条数

## 匹配打分（score）

对每条金句计算得分：

1. **关键词重叠**（主信号）：将稿件分词（jieba；缺失时 CJK 二元组降级），每条 ≤2 字的关键词若为金句 `text/tags/book/category` 的子串，得分 += 词长（短语越长权重越高）。
2. **分类/主题匹配**（强信号）：若稿件直接出现某金句分类名（如「财富」「沟通」），或命中该分类，得分 += 6。
3. **热度微加权**：公域金句 `+= log10(popularity+1) * 0.4`。

## 筛选与保底

- 按得分降序，先做**多样性约束**：同一本书最多取 2 条，避免金句来源扎堆。
- 取前 `max` 条作为候选。
- **保底逻辑**：若匹配（score>0）的候选不足 `min`，按「热度 + 分类就近」放宽补到 `min` 条，并在报告中标注 `保底(弱匹配)`，提醒你人工复核——宁可插得弱也不低于 3 条，但弱匹配会显式标出。

## 插入位置

按段落（空行分段，否则按换行）分布插入，保证语境自然：
- 段数 ≥4：插在「钩子后(~25%)」「中段(~50%)」「结尾前(末段前)」三处，必要时再均匀补点。
- 段数少：插在首段后、结尾前等位置。

每条金句以引用块呈现，标注出处与分类：
```
> 💡 「金句原文」
> —— 《书名》作者 [分类·热门/个人]
```

## 置信度

- `高`：分类命中且 score≥8
- `中`：score≥4
- `低`：0<score<4
- `保底(弱匹配)`：score=0 时被补入

## 输出

- 增强稿写入 `--out`（默认 `<原名>_with_golden.md`）。
-  stdout 打印**插入报告**：每条的插入位置、置信度、得分、命中关键词，便于你一眼判断「插得对不对」。

## 最佳实践

- 稿件里**显式写出主题词/分类名**（如「今天聊财富自由」「讲沟通」），能显著提升匹配精度。
- 插入后建议人工过一遍，把生硬处改为自然口播衔接（金句是素材，不是必须原样照搬）。
